# Заметки к ростку · Задание 6

Находки и улучшения, которые относятся к общему движку (`seed/swa/`), а не к отдельному сайту. Правка фиксируется для ростка один раз и тиражируется на все сайты серии (AGENTS.md §1).

## 1. Жестко зашитый ключ хранилища swa-bash-search в assets/search.js

- **Что.** В скрипте поисковой панели `assets/search.js` (строки 59, 69, 72) сохранение и чтение состояния поискового запроса в `sessionStorage` выполнялось по жестко зашитой строке `'swa-bash-search'`. В то же время базовый движок сайта `assets/swa.js` (строки 8, 225, 290) динамически формирует ключ на основе атрибута тега `html`: `const key = (name) => 'swa-' + (document.documentElement.dataset.site || 'swa') + '-' + name`. На всех сайтах серии, отличных от `bash` (например, `sre-observability` с `data-site="obs"`), при переходе из поисковой выдачи на другую страницу (`10.html`, `navigator.html`, `glossary.html`) целевая страница искала ключ `'swa-obs-search'`, получала `null` и не вызывала функцию `applySearchHighlight()`. В результате в контенте не подсвечивались найденные слова тегом `<mark class="search-mark">`, а в шапке сайта не появлялась кнопка сброса подсветки `.clear-mark-btn`.
- **Чем доказано.** Замер Playwright на `courses/observability` при переходе из поиска `ru/01.html` на `ru/10.html#metrics-export`: `sessionStorage.getItem('swa-bash-search')` содержал сохраненный JSON, тогда как `sessionStorage.getItem('swa-obs-search')` возвращал `null`; количество элементов `mark.search-mark` было равно 0, а свойство `clearBtn.hidden` оставалось `true`.
- **Как обойдено на сайте.** В `seed/swa/assets/search.js` объявлены константа `const SITE = document.documentElement.dataset.site || 'swa'` и генератор `const key = (name) => 'swa-' + SITE + '-' + name;`, а все вызовы `sessionStorage` переведены на `key('search')`. Изменение передано в росток (коммит `aa270fc` в `ai-factory-builder`) и синхронизировано на сайт коммитом `8900b28`.
- **Что предлагается для ростка.** Зафиксировать динамический ключ `key('search')` в `seed/swa/assets/search.js` как канонический платформенный стандарт для всех существующих и будущих сайтов серии.

## 2. Утечка специфичности селектора nav.contents .nav-extra a на вложенное оглавление

- **Что.** При реализации стандарта Active Tool Promotion сквозной инструмент на своей странице (`navigator.html`, `glossary.html`) поднимается на первое место в `.nav-extra`, а скрипт `assets/swa.js` монтирует локальное оглавление `#pageToc` внутрь контейнера этой активной ссылки. Селектор `nav.contents .nav-extra a` в `assets/style.css` был объявлен контекстным (без дочернего комбинатора `>`) и обладал специфичностью (0, 2, 2). Он захватывал все ссылки оглавления `.toc-list a` и перебивал правило активного пункта `.toc-list a.active` со специфичностью (0, 2, 1), принудительно выставляя свойство `border-left: 3px solid transparent`. Из-за этого янтарная вертикальная полоса активного раздела оглавления на страницах Навигатора и Словаря оставалась невидимой (`rgba(0, 0, 0, 0)`).
- **Чем доказано.** Замер вычисленных стилей через Playwright на странице `ru/navigator.html`: элемент `#tocList a.active` имел `borderLeftColor: 'rgba(0, 0, 0, 0)'` вместо `var(--term-accent)` и `display: 'flex'` вместо `display: 'block'`.
- **Как обойдено на сайте.** В `seed/swa/assets/style.css` селекторы кнопок инструментов ограничены до прямых потомков через `nav.contents .nav-extra > a, nav.contents .nav-extra > div > a`, а для `.toc-list a.active` явно зафиксирована рамка `border-left: 3px solid var(--term-accent)`. Синхронизировано из ростка коммитом `99de7f7`.
- **Что предлагается для ростка.** Сохранить строгую изоляцию дочерних ссылок `.nav-extra` в `seed/swa/assets/style.css`, исключающую стилизацию элементов вложенного `#pageToc`.

## 3. Обязательность центрирующего контейнера div.wrap на посадочных страницах

- **Что.** В базовых стилях платформы `assets/style.css` центрирование сетки сайта и ограничение максимальной ширины чтения задаются правилом `.wrap { max-width: 68rem; margin: 0 auto; padding: 0 16px 64px; }`. При ручной или автоматической генерации локализованных посадочных страниц (`en/index.html`, `uk/index.html`, `de/index.html`) пропуск тега `<div class="wrap">` приводил к тому, что шапка и блок `.cols` растягивались на 100% ширины широкоформатных дисплеев, ломая пропорциональное масштабирование шрифта по кнопкам «A A A».
- **Чем доказано.** На мониторе шириной 1920px ширина основного текста на страницах `en/index.html`, `uk/index.html`, `de/index.html` составляла 1920px (строка растягивалась на весь экран), в то время как на `ru/index.html` она строго удерживалась в пределах 1088px (`68rem` при базовом шрифте 16px).
- **Как обойдено на сайте.** На страницах `en/index.html`, `uk/index.html`, `de/index.html` добавлен открывающий тег `<div class="wrap">` непосредственно перед `<header class="top">`. Playwright подтвердил идентичную ширину 1088px на всех 4 языках.
- **Что предлагается для ростка.** Проверить все шаблоны `seed/swa/pages/shell-*.html` и генератор `tools/new-site.py` на обязательное присутствие `<div class="wrap">` сразу после ссылки `<a class="skip">`.
